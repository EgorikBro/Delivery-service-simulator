# Практическое задание 1. Консольный симулятор службы доставки

Консольное приложение на Java, которое моделирует работу небольшой службы доставки:
создание заказов, выбор способа доставки, назначение курьера и ведение заказа по статусам.
Приложение предназначено для оператора службы доставки.
Все данные хранятся только в памяти — без базы данных, файлов, сети и графического интерфейса.

## Возможности

- Создание заказа с данными клиента, адресом доставки и одной или несколькими позициями
- Просмотр списка существующих заказов
- Выбор способа доставки с расчётом стоимости и ориентировочного срока
- Назначение курьера, если выбранный способ доставки это предусматривает, и смена курьера
- Изменение статуса заказа с проверкой допустимости перехода
- Обработка некорректного ввода с понятными сообщениями для пользователя

## Способы доставки

| Способ               | Стоимость                                 | Срок          | Курьер       |
|----------------------|-------------------------------------------|---------------|--------------|
| Стандартная доставка | 300 руб., бесплатно при заказе от 5000 руб. | 3 дня       | требуется    |
| Экспресс-доставка    | 500 руб. + 5% от суммы заказа             | 1 день        | требуется    |
| Самовывоз            | бесплатно                                 | в день заказа | не требуется |

Каждый способ доставки реализует общий интерфейс `DeliveryMethod` и сам рассчитывает
стоимость и срок — код оформления заказа не зависит от конкретного типа доставки.

## Статусы заказа
```
CREATED → CONFIRMED → IN_DELIVERY      → DELIVERED
                    ↘ READY_FOR_PICKUP ↗   (самовывоз)

CREATED, CONFIRMED → CANCELLED
```

- Подтвердить заказ можно, только если в нём есть товары и выбран способ доставки
- Товары и способ доставки меняются только до подтверждения
- Курьер назначается подтверждённому заказу; сменить курьера можно до передачи заказа в доставку
- `IN_DELIVERY` — только для курьерской доставки с назначенным курьером,
  `READY_FOR_PICKUP` — только для самовывоза
- После доставки или отмены курьер снова становится свободным

## Технологии

- Java 17
- Maven

## Сборка и запуск

Требуется установленная JDK 17+ и Maven.
```
mvn compile
mvn exec:java
```
Также можно открыть проект в IntelliJ IDEA и запустить класс `delivery.Main`.

## Структура проекта
```
src/main/java/delivery/
├── model/       сущности: Client, Courier, OrderItem, Order, OrderStatus
├── delivery/    контракт DeliveryMethod и его реализации:
│                StandardDelivery, ExpressDelivery, PickupDelivery
├── service/     управление данными: OrderService, CourierService
├── ui/          взаимодействие с консолью: ConsoleUI, InputReader, OrderPrinter
└── Main.java    точка входа: создаёт объекты и запускает меню
```

- **model** — сущности и бизнес-правила: каждая операция проверяет свою допустимость
- **delivery** — полиморфный расчёт стоимости и срока доставки
- **service** — хранение заказов и курьеров в памяти, поиск по номеру
- **ui** — ввод с проверкой, вывод информации и меню

Ошибки бизнес-правил передаются стандартными исключениями `IllegalArgumentException`
и `IllegalStateException`, консольный интерфейс выводит их пользователю понятным сообщением.

## Работа с репозиторием

- Ветка main содержит только проверенный код; прямые коммиты в неё не делаются
- Каждая задача ведётся в отдельной ветке (feature/..., fix/..., docs/...)
- Изменения попадают в main через Pull Request после ревью второго участника
- Сообщения коммитов оформляются так:
  feat:, fix:, refactor:, docs:, chore:
